# Spec 001 — Hub

The hub is a minimal place to choose an operator-defined Pokémon ROM and run it with EmulatorJS. The current web screen contains one square box per configured ROM: a cover area for game artwork when available, a green button with a white Play icon, and a readable title and ROM metadata strip. The dark green theme remains. Play opens the emulator in a floating container near the top of the same screen. The container blocks interaction with the hub behind it, scales to the viewport while preserving its 3:2 aspect ratio, and offers close and container fullscreen controls. The browser page itself does not become the fullscreen target. There is no introductory or game-details page. New behavior or UI belongs in a later user-directed spec.

The backend owns the list and checks each manually supplied ROM against an expected hash before it can launch. Players do not add titles or upload ROMs through the hub. A hash from an independent ROM reference identifies a known dump; the backend's SHA-256 in the catalog detects later changes to the local file. Client-side emulation still sends ROM bytes to the user's device.

React keeps EmulatorJS in a generic iframe, as required by the [official SPA embedding guide](https://emulatorjs.org/docs/embed/). The backend supplies the game's ROM URL and core; the frontend has no hard-coded Pokémon title list. [Spec 003](003-first-playable-hub.md) defines this first runnable web slice.

Cloud saves are deferred to [Spec 002](002-cloud-saves-and-content.md). Electron may later reuse the compiled frontend and open multiple emulator windows, as previously requested; that behavior is not part of the current web screen. Mobile behavior is undefined.
