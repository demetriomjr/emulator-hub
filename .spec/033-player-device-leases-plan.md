# Player Device Leases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce one live browser-device writer for each profile/game save while allowing an immediate same-browser lease handoff after reload.

**Architecture:** A Redis-backed lease coordinator owns atomic acquire, renew, release, expiry and fence transitions keyed by profile/game. The backend issues an opaque HttpOnly device cookie and applies the coordinator to player acquire/heartbeat/release routes and save writes. Each iframe owns a generated frontend session ID, starts heartbeating before EmulatorJS boot, and stops itself when fenced.

**Tech Stack:** Node.js HTTP server, Redis persistence Lua transitions, React, browser Fetch and HttpOnly cookies, Node test runner.

**Spec:** `.spec/033-player-device-leases.md`

## Global Constraints

- Do not run a project build.
- `deviceId` is backend-issued only; frontend code never reads or writes it.
- Session IDs are generated by the frontend per emulator iframe and are not persisted.
- Lease identity is exactly `(profileId, gameId)`; all ownership transitions and save fences are serialized on that identity.
- Lease heartbeat is 5 s and expiry is 45 s.
- Active leases remain visible in the profile picker but disable open, rename and delete.
