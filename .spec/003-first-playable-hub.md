# Spec 003 — First playable web slice

Show configured Pokémon ROMs as square boxes with a cover area, a green button with a white Play icon, and the ROM name in its own title strip. The subsequent card metadata change is in [Spec 004](004-rom-card-metadata.md). Keep the dark green theme. Play embeds one generic EmulatorJS iframe in a modal floating container on the same screen. The underlying boxes remain visible but cannot be operated until the container closes. Size the container to the viewport with a fixed 3:2 aspect ratio. Its fullscreen control uses the container as the fullscreen element; the player stays proportional and centered. Avoid scrolling when the content fits. Add no game page, hero, footer, or status badge. See [Spec 001](001-hub.md) for the product context.

The operator puts a ROM in Git-ignored `apps/backend/roms/` and records its ID, name, system, core, filename, and expected SHA-256 in `apps/backend/catalog.json`. The expected hash must trace to an independently verified copy. The backend returns the catalog at `GET /api/games`, a launch descriptor at `GET /api/games/{id}/launch`, and verified bytes at `GET /roms/{id}`. A missing or mismatched ROM has disabled Play. The backend checks the hash again before delivering bytes.

The React frontend requests the catalog. Play asks the backend for the launch descriptor, then embeds `player.html` without navigating away. This generic iframe configures EmulatorJS 4.2.3 with the returned core and ROM URL. The [EmulatorJS SPA guide](https://emulatorjs.org/docs/embed/) requires iframe isolation. The container has close and fullscreen icon controls; emulator-specific controls are left as supplied by EmulatorJS until a later decision. `GET` and `HEAD` on the ROM endpoint both return verified `Content-Length`; `HEAD` has no body because EmulatorJS checks previously loaded content that way.

Acceptance: a matching ROM opens and runs within the screen; a missing or changed ROM cannot launch; opening the same ROM again works. No build is required for local development. Saves, Electron windowing, and mobile behavior are outside this slice.

Verification on 2026-09-15: the operator supplied Pokémon Emerald (USA, Europe). Its SHA-1 matched the [No-Intro-sourced reference](https://tasvideos.org/Games/358/Versions/View/2602); its local SHA-256 was recorded as the backend baseline. The browser showed the ROM, launched EmulatorJS, displayed the game intro, and returned to the catalog. A repeat launch initially failed because the backend rejected EmulatorJS's `HEAD` request; after adding verified `HEAD` metadata, the repeat launch ran the game. The backend regression suite passed 7/7 without a build.
